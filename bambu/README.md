# Bambu Studio settings template

`project_settings.config` is the full settings file Bambu Studio writes into
every project it saves: printer, nozzle, filaments in the AMS slots and every
process setting. Every build script copies it into the 3MFs it writes
(`write_bambu_project` in `bambu_project.py`, next to it), so a 3MF opens in Bambu
Studio as a project, ready to slice, instead of "generated by old Bambu Studio,
load geometry data only".

On top of the template, each design's `params.yaml` can set:

- `print.project`: settings for every part in its 3MFs;
- `print.<part>`: one part's own settings, which show in Bambu Studio as that
  object's overrides in the object list.

Keys and values are Bambu Studio's own (`sparse_infill_density: 15%`,
`sparse_infill_pattern: gyroid`, `seam_position: back`,
`wall_generator: arachne`, `wall_loops: 4`, `wall_sequence: inner-outer-inner wall`
and so on). The writer refuses a key the template doesn't have. Every key is
listed in `project_settings.config`.

`print_settings_id` picks another of Bambu Studio's process presets, for example
`print_settings_id: 0.12mm High Quality @BBL H2C` (the Omniwall hooks). The
writer switches to it the way Bambu Studio does: every setting the template
leaves at its preset's value takes the new preset's, and the template's own
changes stay. It needs both presets saved in `process/`, with everything they
inherit filled in, from this machine's Bambu Studio install:

```
uv run --no-project python bambu/save_process.py "0.12mm High Quality @BBL H2C"
```

The current template was saved by Bambu Studio 02.08.04.57 for Zeid's **Bambu
Lab H2C 0.4 nozzle**, 0.20mm Standard, with Bambu PETG Basic in five AMS slots
(grey, black, white, red, orange), from `h2c.3mf` (2026-10-21). Changed from
the preset: Arachne walls, seam at the back, zig-zag sparse infill, arc fitting
off, print sequence by object, slice gap closing radius 0.02 and resolution
0.004. Walls stay at the preset's 2; a design that needs more sets them in its
`params.yaml`.

By object, Bambu Studio refuses to slice a plate whose parts (any taller than
the 4 mm nozzle) sit closer than the print head's clearance: on the H2C 90 mm
apart conflicted and 100 mm sliced. `bambu_object_gap()` gives the gap to use
(104 mm), and parts taller than the head's clearance under its rod (47.4 mm)
go on plates of their own.

## Changing the printer or filament

Set up a project in Bambu Studio with the printer, filaments and process you
want, save it, then from the repo root:

```
uv run --no-project python bambu/update_template.py path/to/saved.3mf
```

and rebuild the designs. The settings in each `params.yaml` stay on top.
